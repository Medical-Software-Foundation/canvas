{% comment %} One template, two modes: add (a named patient, nothing stored yet) and edit (an existing entry). They ask for the same fields against the same validator, so a second template would be the same form twice -- and the two copies would drift, which is how the service select came to default to a concrete appointment type in one place and "any" in another. What differs is the load and the save: add fetches the patient and POSTs, edit fetches the entry and PUTs. Both are below, chosen from ``config.mode``. It wears the roster's own stylesheet and the roster dialog's own classes rather than inlining a copy. The inline copy is what reviewers rejected: it had its own spacing, sentence-case labels and no action bar, so the form the chart opened and the form the roster opened were visibly two different forms. The only thing intentionally absent here is the patient picker -- the chart already knows who this is about, and an edit cannot reassign the patient. {% endcomment %}
